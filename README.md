# MoonMuse Custom Studio

A responsive React/Vite storefront and customization experience for a handmade gifting studio.

## Live website

[Visit MoonMuse](https://moonmuse-beta.vercel.app)

## Run locally

```bash
npm install
cp .env.example .env
npm run dev
```

The UI works without environment variables using seeded demo content and localStorage for the editor/order demo. For production, create a Supabase project, run `supabase/schema.sql`, populate `.env`, and connect the form service to a server-side Supabase Edge Function. Keep the Supabase service-role key and Resend API key only in Edge Function secrets.

## Included

- Public shop, studio selector, Konva editor, design-service form, preview, order request, gallery, status and About pages
- Responsive editorial visual system and original generated seed photograph
- Private `/admin` dashboard shell (replace demo sign-in with Supabase Auth before production)
- Normalized PostgreSQL schema, storage buckets and RLS policies
- Editor JSON persistence and high-resolution PNG preview export
- File type and 10 MB client-side validation in the editor

## Production handoff

Implement the order Edge Function with Turnstile/rate limiting, input sanitization, order-number generation in PostgreSQL, private uploads, and Resend notifications. Never expose `SUPABASE_SERVICE_ROLE_KEY` or `RESEND_API_KEY` through `VITE_` variables.

Run `supabase/schema.sql` in the Supabase SQL editor, create Janvi's Auth user,
and set that user's `profiles.role` to `owner`. Deploy functions from
`supabase/functions`, then set `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`,
`OWNER_NOTIFICATION_EMAIL`, `PUBLIC_SITE_URL`, and `TURNSTILE_SECRET_KEY` as
Supabase Function secrets. Only the URL and anonymous key belong in the Vite
environment. Private customer designs and chat files must be served with short-
lived signed URLs generated by an authenticated server function.

Cloudflare Pages settings: build command `npm run build`, output directory `dist`, SPA fallback enabled.
